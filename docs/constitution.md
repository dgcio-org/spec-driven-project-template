# 项目宪法 — DGCIO 数据工程规范

> 不可违背的基本原则。所有 Agent 和人类贡献者必须遵守。
> 与 `project-rules.md` 的区别：rules 可以随项目演进修改，constitution 基本不动。

## 工程原则

1. **Spec 先行** — 任何代码变更必须有对应的 spec 或 change-proposal
2. **CI 必须通过** — PR 合并前 CI 全绿（含 dry-run 爬虫验证）
3. **不跳步** — 讨论未达成共识不写代码
4. **最小变更** — 只改必须改的，不扩大范围
5. **BREAKING CHANGE 需要 explicit approval** — 显式确认才能引入破坏性变更

## 数据工程专项原则

1. **去重优先** — 所有数据采集管线必须有去重策略（日期窗口 + URL 缓存或等效机制）
2. **异常可见** — 数据源不可达、格式变化、空结果必须有日志记录，关键时刻告警
3. **增量优于全量** — 尽量增量采集，避免对目标站点造成不必要压力
4. **反爬合规** — 遵循目标网站的 robots.txt，合理控制访问频率，使用合法 User-Agent
5. **数据不可变** — 原始采集数据写入后不修改，清洗和处理在独立管线完成

## 安全约定

1. `.env` 不入 git
2. 密钥由用户自行管理（GitHub Secrets 或本地 .env）
3. 高风险操作（删文件、推远程、改环境/CI/DB、修改爬虫目标）须取得二次确认
4. 爬虫发出的请求不得包含真实用户身份信息

## 技术选型约束

- 优先使用免费云端方案（GitHub Actions 定时调度 + 公开 API）
- 不引入需要自建服务器的依赖（除非项目核心需求）
- Python 为默认语言（数据工程生态成熟）
- 数据存储优先考虑文件（JSON/CSV）或免费云服务，不自建数据库
- HTTP 请求统一使用 `requests` 或 `httpx`，不引入浏览器自动化（除非目标站点强依赖 JS 渲染）

## 兼容性约定

- 向后兼容为默认原则
- 数据源变更时先通知下游，保留至少一个大版本过渡期
- 废弃的 API/数据字段标注 `@deprecated` 并保留至下个大版本
