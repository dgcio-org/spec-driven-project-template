# 项目宪法

> 不可违背的基本原则。所有 Agent 和人类贡献者必须遵守。
> 与 `project-rules.md` 的区别：rules 可以随项目演进修改，constitution 基本不动。

## 工程原则

1. **Spec 先行** — 任何代码变更必须有对应的 spec 或 change-proposal
2. **CI 必须通过** — PR 合并前 CI 全绿
3. **不跳步** — 讨论未达成共识不写代码
4. **最小变更** — 只改必须改的，不扩大范围
5. **BREAKING CHANGE 需要 explicit approval** — 显式确认才能引入破坏性变更

## 安全约定

1. `.env` 不入 git
2. 密钥由用户自行管理
3. 高风险操作（删文件、推远程、改环境/CI/DB）须取得二次确认

## 工具链约束

> 初始化项目时根据实际情况填写。

- 优先使用免费云端方案
- GitHub Actions 免费额度内调度
- 不引入需要自建服务器的依赖（除非项目核心需求）

## 兼容性约定

> 初始化项目时根据实际情况填写。

- 向后兼容为默认原则
- 废弃 API 需标注 `@deprecated` 并保留至少一个大版本
